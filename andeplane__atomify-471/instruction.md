## Problem
Quick-running or creating a project from the [examples template](https://github.com/andeplane/atomify-examples-template) failed with "Could not download 2d-msd-diffusion.ipynb (HTTP 404)".

`exampleProjectFiles` appended `analysisScript` as an extra file to download, resolved as `{baseUrl}/{analysisScript}`. In the template (and in the bundled "2D diffusion coefficient MSD" example) `analysisScript` is just the name of a notebook that is already in `files`, so Atomify fetched `.../main/2d-msd-diffusion.ipynb` (404) instead of `.../main/2d-msd-diffusion/2d-msd-diffusion.ipynb`, and project creation is all-or-nothing.

## Changes
- Skip the extra download when `analysisScript` names a file already listed in `files`. A notebook outside the list is still fetched.
- Resolve example URLs with `new URL()`. `baseUrl` is now optional and defaults to the folder containing `examples.json`, so forks and local servers work without editing it. Absolute URLs pass through; a relative `baseUrl` keeps its old app-relative meaning (the bundled `"baseUrl": "examples"`).
- No longer mutates the fetched JSON, checks the examples.json response status, and skips `descriptionFile` when it is unset.

## Testing
- New unit tests for URL resolution and `exampleProjectFiles`; full `vitest run` (643 tests), `tsc`, prettier and lint pass.
- Ran the dev server in Playwright with the template's examplesUrl, clicked Quick run on 2D diffusion MSD: the run starts and no request returns 4xx.
