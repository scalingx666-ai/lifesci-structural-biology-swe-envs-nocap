Before: the ~23 Playwright e2e tests in `e2e/` only ran when someone ran `npm run e2e` locally; no CI workflow ran them.

After: a new `.github/workflows/e2e.yaml` (pull requests and pushes to main) builds the production app, including the JupyterLite site, and runs a Chromium smoke subset against it with `vite preview`. If it fails, the Playwright report and traces are uploaded.

How: smoke tests carry an `@smoke` tag in their title. That covers run.spec (engine load and a full run), both library.spec tests (project lifecycle and zip export/import), quickrun.spec (example library quick run plus save as project) and notebook.spec (the notebook iframe target). `playwright.smoke.config.ts` extends `playwright.config.ts` with `grep: /@smoke/`. It serves the build with `vite preview` on port 5201; `preview.headers` already sets COOP/COEP in `vite.config.ts`. It also adds an HTML reporter on CI. `npm run e2e:smoke` runs it. Playwright browsers are cached on the `@playwright/test` version, and `playwright install --with-deps chromium` still runs on a cache hit to get the system libraries. continue-run.spec is not in the subset. It, like atom-radii, atom-tags, data-viewer, group-colors, lighting, particle-attributes, ssao-quality and units, imports `/atomify/src/store/index.ts`, which only the dev server serves. These specs can't run against a production build. Non-smoke specs are unchanged.

Testing: `npm run typecheck`, `npx vitest run` (486 passed), `make jupyter` + `npm run build`, smoke config twice locally (library ×2, notebook and quickrun passed both times). run.spec could not pass locally: Monaco loads from cdn.jsdelivr.net, which this sandbox blocks. This PR's own CI run is its first real check. The full suite ran against the dev server as well, with the same Monaco limitation.
