<details>
<summary>Release notes</summary>
<p><em>Sourced from <a href="https://github.com/modular-bitfield/modular-bitfield/releases">modular-bitfield's releases</a>.</em></p>
<blockquote>
<h2>v0.12.0</h2>
<h1>Breaking changes</h1>
<ul>
<li>The MSRV is now 1.70. This is not currently a hard requirement of modular-bitfield itself but is instead the path of least resistance due to changes to underlying dev-dependencies, so please open a ticket if you really need support for an even older version of Rust.</li>
<li>The <code>InvalidBitPattern::invalid_bytes</code> field is now private. Use the <code>InvalidBitPattern::invalid_bytes()</code> method to access the invalid bytes (and <code>InvalidBitPattern::new()</code> to create new errors).</li>
</ul>
<h1>Deprecations</h1>
<ul>
<li>To conform with idiomatic Rust code, the derive macro <code>#[derive(BitfieldSpecifier)]</code> has been renamed to <code>#[derive(Specifier)]</code> because it derives the <code>Specifier</code> trait. The deprecated alias will be removed in the next release of modular-bitfield.</li>
</ul>
<h1>Enhancements</h1>
<ul>
<li>The syn dependency has been updated to version 2.</li>
<li>Generated constructors and getters are now annotated with <code>#[must_use]</code>. (<a href="">#79</a>)</li>
<li>Structs with const generics can now use <code>#[bitfield]</code>. (<a href="">#87</a>)</li>
</ul>
<h1>Bug fixes</h1>
<ul>
<li>Enumeration variant names will no longer conflict with code generated by <code>#[derive(Specifier)]</code>. (<a href="">#82</a>)</li>
<li>Using <code>#[bitfield]</code> on an empty struct now emits an appropriate diagnostic instead of causing a compile-time arithmetic error. (<a href="">#104</a>)</li>
<li>Various fixes to lints. (<a href="">#62</a>, <a href="">#66</a>, <a href="">#93</a>, <a href="">#95</a>. Thanks, <a href="https://github.com/dimpolo"><code>@​dimpolo</code></a>, <a href="https://github.com/diseraluca"><code>@​diseraluca</code></a>, <a href="https://github.com/nilfit"><code>@​nilfit</code></a>, and <a href="https://github.com/LDVSOFT"><code>@​LDVSOFT</code></a>!)</li>
<li>Various fixes to documentation formatting. (<a href="">#91</a>, <a href="">#101</a>, <a href="">#103</a>. Thanks, <a href="https://github.com/00xc"><code>@​00xc</code></a>, <a href="https://github.com/SebastianJL"><code>@​SebastianJL</code></a>, and <a href="https://github.com/jruderman"><code>@​jruderman</code></a>!)</li>
<li>When automatically deriving <code>Debug</code>, tuple-like structs are now formatted normally instead of like structs with numeric fields.</li>
</ul>
</blockquote>
