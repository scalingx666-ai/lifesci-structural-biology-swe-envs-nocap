Before: projects duplicated before #400 still have `source: { type: "example", exampleId }` in their project.json, so every run of them reports the original example's id to Mixpanel (`Run.Start`, `Run.Finish`, `Simulation.Start`) and inflates that example's numbers.

After: opening such a project rewrites its source to `{ type: "duplicate" }` on disk, once, and its runs report as a normal project. Genuine example projects, renamed or not, and quick projects are left alone.

How: `openProject` checks a new `isStaleExampleCopy(meta)`: an example source whose display name ends in "(copy)" or whose dirName ends in `-copy` / `-copy-N`, which is how `duplicateProject` names copies. Comparing dirName with `exampleId` doesn't work, because example projects get `dirName = slug(displayName)`. Unit tests cover the check, and integration tests cover the on-disk rewrite, the metrics payload afterwards, and the untouched cases.
