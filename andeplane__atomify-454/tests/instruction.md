**Before:** The starter `analysis.ipynb` (ADR-002 §2) was Python written as TypeScript string arrays in `src/utils/AnalyzeNotebook.ts`, so you couldn't open, edit or lint it as a notebook. The JupyterLite URL `/atomify/jupyter/lab/index.html` was hard-coded in `src/containers/Notebook.tsx`, repeating the Vite `base`. That file's default-export component was dead code left over from the removed embedded mode (only its own test imported it). Its ".ipynb lookup" was also copied in `NotebookTab.tsx`.

**After:** The notebook is a real nbformat 4 file, `src/notebooks/analysis.template.ipynb`. It is imported with `?raw`, and `{{displayName}}` / `{{description}}` placeholders are filled in for each project. The generated notebook is byte-for-byte the same as before. The Jupyter URL now comes from `import.meta.env.BASE_URL`. CI compiles the template's code cells with Python.

**How:** `projectAnalysisNotebook` parses the template, joins each cell's line-array source into one string (the same shape as before) and fills placeholders in a single pass with a replacer function. That means `$` patterns or `{{…}}` in user-supplied names stay literal. `src/containers/Notebook.tsx` and its test are removed. Its live parts are now in `src/shell/notebookUrl.ts`: `jupyterLabUrl` (handles a base with or without a trailing slash), `notebookUrlFor`, and `findProjectNotebook`, which replaces the duplicated lookup. `scripts/check_notebook_template.py` compiles each code cell, skipping lines that start with `%` or `!` and allowing top-level await. It runs in `deploy.yaml` right after "Set up Python".

**Testing:** `npm run typecheck`; `npx vitest run` (42 files, 493 tests pass), with new tests for the parsed template's cells, the substituted values and the URL helpers. I compared `JSON.stringify` output from the old and new generators, with and without a description and with tricky `$`/`{{}}` inputs: identical. `nbformat.validate` passes on the template. The check script passes on the template and catches a deliberately broken cell.
