## Summary of the Pull Request  
<!-- Describe what changes were made to the code, what was added, removed, etc. -->

This PR adds a new capability of defining custom toppar per module instead of globally, this increases the granularity and is relevant when processing an ensemble of heterogeneous ligands.

To achieve this I updated the pdb ontology to contain the ligand toppar as a property, so this can be carried forward in the modules.

I also added backwards compatibility, so its still possible to define a global custom toppar fname, but when using `autoppar=true` and an ensemble of ligands each will inherit the correct toppar generated by prodrg.
