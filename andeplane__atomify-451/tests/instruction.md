**Title:** Remove legacy menu gate and fix silent viewport toasts

Before: Particle streaming and the viewport keyboard shortcuts depended on `app.selectedMenu === "view"`. That string was left over from the removed menu shell (ADR-003), and the shell set it to `"view"` or `"shell"`. The speed and camera-copy toasts in `Simulation.tsx` used antd's static `notification` API, which shows nothing under React 19. The camera-copy shortcut (`c`) read `window.visualizer`, but nothing ever assigned it, so the shortcut did nothing.

After: The gate is now a boolean, `app.liveViewportVisible`. The shell sets it exactly as before: true while the live run-detail screen for the active run is visible. Shortcut toasts and the "Failed to load LAMMPS" error toast now appear, and `c` copies the camera from `render.visualizer`. Dead legacy state is gone: `preferredView`/`setPreferredView`, `selectedFile`/`setSelectedFile` (`newSimulation` wrote it, nothing read it) and `src/global.d.ts` (`window.visualizer`, `window.files`).

How: `SimulationComponent` is already mounted inside `ShellUIContext.Provider` in `Shell.tsx`, so it now calls `useShellUI().notify`. `processing.ts` reads `app.liveViewportVisible` in both of the places it gates rendering. I checked every removal with grep across `src/` and `e2e/`. The e2e tests already use `render.visualizer`.

Testing: `npm run typecheck`, `npx vitest run` (42 files / 485 tests pass). New tests cover: notify toasts on speed change, camera copy from the store visualizer, shortcuts ignored while the viewport is hidden, and the `liveViewportVisible` store default and setter.
