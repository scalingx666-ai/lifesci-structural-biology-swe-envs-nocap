## Problem
Overrides and sweeps from the New run dialog had no effect. `prepareVarsScript` prepended `variable T equal <override>`, but LAMMPS lets a later `variable T equal 1.44` redefine an equal-style variable (only index/loop styles are skipped when already defined), so the script's own line won. A sweep of T = 1, 2 ran both points at T = 1.44; `run.json` still recorded `{T:1}`/`{T:2}`, which is why the e2e passed.

## Fix
- New `applyVariableOverrides` in `src/utils/scriptVariables.ts` rewrites the first plain-number definition (the one the dialog lists) in the engine's copy of the script, keeping indentation and trailing comment. Later redefinitions (e.g. a second stage) are left alone; a variable the script doesn't define is prepended.
- `prepareVarsScript` writes only the rewritten `_wrapper_<script>`; the unused `_vars_` file is gone.
- Corrected the module comment, the `buildCommandPreview` doc, and the dialog text (no `-var` flags are actually passed).

## Tests
- New `scriptVariables.test.ts`; updated `RunController.test.ts`.
- `e2e/sweep.spec.ts` now prints `SWEEP_T=${T}` and asserts each run's `log.lammps` shows 1 and 2, not 1.44. Ran locally: passes with the fix, fails with the old prepend behavior (`SWEEP_T=1.44`).
- typecheck, vitest (654 tests), lint, prettier all pass locally.
